# motely-wasm 31.0.0

The engine hands JavaScript what a UI draws, so consumers stop translating.

## New

- **`motely-wasm/jaml`: JAML as TypeScript types.** `JamlFilter`, `JamlClause`, every clause and
  source block, and every enum as its canonical names (`MotelyJokerName`, `MotelyDeckName`, …),
  generated by `motely schema` from the same vocabulary the loader binds. A filter is plain JSON:
  build a `JamlFilter`, pass `JSON.stringify(filter)` to `JamlConfigLoader.check` / `fromJaml`.
  The JSON Schema ships beside it as `motely-wasm/jaml/schema.json`.
- **`JamlConfigLoader.toJson(yaml)` and `JamlConfigLoader.toYaml(json)`.** A filter moves between
  YAML and JSON through the engine, keys, order and values as written, so JavaScript holds every
  filter as one `JamlFilter` and never parses YAML. Unquoted scalars are typed as YAML 1.2 reads
  them; quoted ones stay strings. Comments do not survive the trip to JSON. Text that does not
  parse throws, and `Errors.last()` names the line.
- **`MotelyJamlyzerLegendary.item`.** Each Soul's legendary as a `MotelyItem` (the engine's
  `new MotelyItem(joker, edition)`), the same shape as every shop and pack card in the result.
- **`MotelyJamlyzer.defaultShopSlots(ante)` and `MotelyJamlyzer.packCount(ante)`.** The shop
  depth (15 for antes 0–1, 50 beyond) and pack count (4 for antes 0–1, 6 beyond) the Jamlyzer
  walks, so a UI can lay out an ante before it has a result. Pack indices in `sources:` count
  these packs.

## Changed

- `MotelyJamlyzerLegendary` gains the `item` field (record order: ante, packSlot, joker, edition,
  item). Fields that existed in 30 are unchanged.
