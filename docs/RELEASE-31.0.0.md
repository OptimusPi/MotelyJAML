# motely-wasm 31.0.0

The engine hands JavaScript what a UI draws, so consumers stop translating.

## New

- **`motely-wasm/jaml`: JAML as TypeScript types.** `JamlFilter`, `JamlClause`, every clause and
  source block, and every enum as its canonical names (`MotelyJokerName`, `MotelyDeckName`, …),
  generated by `tools/schema.cs` from the same vocabulary the loader binds. A filter is plain JSON:
  build a `JamlFilter`, pass `JSON.stringify(filter)` to `JamlConfigLoader.check` / `fromJaml`.
  The JSON Schema ships beside it as `motely-wasm/jaml/schema.json`.
- **`JamlConfigLoader.toJson(yaml)` and `JamlConfigLoader.toYaml(json)`.** A filter moves between
  YAML and JSON through the engine, keys, order and values as written, so JavaScript holds every
  filter as one `JamlFilter` and never parses YAML. Unquoted scalars are typed as YAML 1.2 reads
  them; quoted ones stay strings. Comments do not survive the trip to JSON. Text that does not
  parse throws, and `Errors.last()` names the line.
- **`MotelyJamlyzerLegendary.item`.** Each Soul's legendary as a `MotelyItem` (the engine's
  `new MotelyItem(joker, edition)`), the same shape as every shop and pack card in the result.
- **`MotelyJamlyzer.defaultShopSlots(ante)` and `MotelyJamlyzer.packCount(ante)`.** The shop
  depth (15 for antes 0–1, 50 beyond) and pack count (4 for ante 1, 6 for every other ante) the
  Jamlyzer walks, so a UI can lay out an ante before it has a result. Pack indices in `sources:`
  count these packs.

## Fixed

- **An ante-0 Soul is opened only when a legendary clause names ante 0.** Ante 0 is in the run
  only after Hieroglyph or Petroglyph, but with no clause naming an ante the Jamlyzer walked it on
  every seed and opened its Soul first, so every later Soul read the next legendary over:
  1YU11111's ante-2 Soul read Yorick, where a run that never plays ante 0 gets Triboulet.
  `soulOrder:` walked ante 0 the same way. Both now open ante 0's Souls only when a
  `legendaryJoker:` or `soulOrder:` clause names ante 0, as a `legendaryJoker:` clause on antes 1
  and up already did; ante 0's cards still show. Ante 0 also offers 6 packs in the Jamlyzer
  (`packCount(0)`), the six a clause has always searched.
- **Souls and Black Holes in Spectral packs follow the game** (9d3e5d6, which landed after 30.0.0
  was published). Balatro's `create_card` makes the Soul check and then the Black Hole check for
  every Spectral card, both on the ante's `soul_Spectral{ante}` stream, and the Black Hole check
  wins. 30 returned The Soul as soon as its check passed: it kept Souls the game turns into Black
  Holes, and every later check in the ante read the stream one roll early. A seed whose Soul was
  one of those no longer matches a `legendaryJoker:` clause: HGX11111 (Ghost, White) has an ante-1
  Spectral pack of Black Hole and Immolate, not The Soul and Black Hole, so 1 of the 460 seeds in
  sequential batch 0 (batchChars 3) with an ante-1 legendary is gone. `SpectralSoulBlackHoleTests`
  pins the game's cards.
- **The Jamlyzer's `legendaryOrder` resamples off the legendaries already held.** It drew every
  Soul's legendary straight off the run's `Joker4` stream, so a second Soul could repeat the
  first one's: BHT11111 (Ghost, White) read Triboulet, Triboulet. In the game, without Showman, a
  legendary you hold drops out of the pool and the draw resamples, which is what every
  `legendaryJoker:` and `soulOrder:` clause already does. The Jamlyzer now walks the same way
  (BHT11111: Triboulet, Canio), so what it shows and what a clause matches agree. `soulOrder` with
  `with: { jokers: [Showman] }` still matches the raw sequence.
- **`soulOrder:` is a list in the schema.** `FilterJsonSchema` described a list of blocks
  (`soulOrder`, `soulOrders`, `entries`) as a single block, so an editor on
  `schema/motely-filter.schema.json` flagged every valid `soulOrder: [...]`; the loader has
  always bound a sequence and refuses a lone block.

## Changed

- **An enum value is a name.** The loader read a number as the enum's value and `A, B` as
  `A | B`, so `erraticRank: 2` bound Four (Two is 0) and `rank: "10"` bound Queen, with no error.
  A number, or a comma list in one scalar, is now an error that names its line and the valid
  names; names still match in any case. `luck:` keeps its numbers, because its value is the
  multiplier (`luck: 4` is X4), but only 1, 2, 4, 5, 8, 16, 32 and 64: `luck: 3` used to bind a
  multiplier no Oops count gives. The JSON Schema admits an integer for `luck` alone. The three
  Erratic filters in `JamlFilters/` wrote `erraticRank: 2` for Two and were searching for Fours;
  they say `Two` now.
- **`motely schema` is now `dotnet run tools/schema.cs`.** The generator reads the vocabulary off
  the JAML types by reflection, which the NativeAOT CLI trims: its trim analysis failed the `aot`
  publish, and an AOT build that ran it wrote a schema missing every clause's own keys. The
  file-based app runs on the JIT and writes the same files, and the CLI no longer carries it.
- `MotelyJamlyzerLegendary` gains the `item` field (record order: ante, packSlot, joker, edition,
  item). Fields that existed in 30 are unchanged.
