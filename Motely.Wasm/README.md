# motely-wasm

Motely in the browser: one JS package, one thread, the engine compiled by NativeAOT-LLVM through
[Bootsharp](https://sharp.elringus.com). The assemblies are embedded in the package, so there is
nothing to host beside the JS, and nothing in `bin/motely-wasm` is patched after the build.

```js
import bootsharp, { Search, Analyze, Jaml } from "motely-wasm";

await bootsharp.boot();

Jaml.check(text);                    // null, or "JAML line 3: ..."

Search.onScored.subscribe((s) => console.log(s.seed, s.score));
const search = Search.settings(text).withSequentialSearch().withBatchCharacterCount(4);
await search.start();                // search.cancel() from anywhere stops it; start() resolves

Analyze.seeds(text);                 // one Jamlyzer result per seed in the filter's `seeds:`
```

## Surface

Four modules, generated by Bootsharp from the interfaces in `Modules.cs`:

| Module | What it does |
|---|---|
| `Search` | `settings(jaml)` returns a `SearchSettings`. Events: `onScored` (one per find), `onProgress`, `onAnalyzed`. |
| `Analyze` | The Jamlyzer: `seeds(jaml)`, `seedsPaged(jaml, eventRolls, shopSlots?)`, `seedsResume(jaml, streamStates, eventRolls, shopSlots?)`. |
| `Jaml` | `check(text)`: null when the filter loads, otherwise the line-numbered reason. |
| `JamlFiles` | `.jaml` files in a folder the user picks. Needs the file-system build below. |

`SearchSettings` is held by reference. Chain `withSequentialSearch`, `withBatchCharacterCount`,
`withStartBatchIndex`, `withEndBatchIndex`, `withSeedList`, `withRandomSearch`, `withKeywordSearch`,
`withDeck`, `withStake`, `withProgressReportIntervalMs`, `withAutoScoreCutoff`, `stopAfter` and
`withAnalysis(eventRolls)`, then `start()`. Afterwards `totalSeedsSearched`, `matchingSeeds`,
`elapsedMs`, `seedsPerSecond`, `completedBatchCount` and `resumeBatchIndex` say what happened.
With `withAnalysis`, each find's full breakdown follows it on `Search.onAnalyzed`, walked in the
same pass, so there is no second call into `Analyze` for a seed the search just found.

Engine enums and records keep their C# names: `MotelyDeck`, `MotelyStake`, `MotelySeedScore`,
`MotelyJamlyzerSeedResult`, and so on.

## Errors

Under NativeAOT a C# exception reaches JS as "C# exception from NativeAOT", without its message.
So the reasons are kept where JS can read them:

- `Jaml.check(text)` gives the reason a filter does not load. `Search.settings` throws on the same
  filters.
- A `with*` call that rejects a value, or a `start()` that rejects, leaves the reason on
  `search.error`.

## Build

```
dotnet workload install wasm-tools
cd Motely.Wasm
dotnet publish -c Release        # bin/motely-wasm
node tests/smoke.mjs
```

Release publish switches on NativeAOT-LLVM and trimming by itself. `wasm-opt` (Binaryen) is
optional: Bootsharp warns when it is missing and the build still works.

## Folder access (optional)

`JamlFiles` needs Bootsharp.FileSystem, a Bootsharp sponsor package served from the rewaffle feed,
so it is off by default and the package builds from nuget.org alone. Turn it on with
`-p:MotelyFileSystem=true` (or `MOTELY_FILESYSTEM=true` in the environment), add the feed as
`nuget.config` describes, and call `fs.init(Bootsharp.FileSystem.FileMounter)` from
`@rewaffle/bootsharp-file-system` before `boot()`. Off, `JamlFiles` keeps the same functions:
`isSupported()` is false, `list()` is empty and the file calls reject.

## Hosts

The package decodes its embedded assemblies with `Uint8Array.fromBase64`: Node 24+, Chrome 140+,
Safari 18.2+, Firefox 133+. An older host needs that function shimmed before `boot()`;
`tests/smoke.mjs` shows one. No COOP/COEP headers and no SharedArrayBuffer are needed.
